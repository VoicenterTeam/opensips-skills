### Added
- **M0 — Repository scaffolding.** Directory structure, GPL-3.0 license, .gitignore, package.json with placeholder scripts, tsconfig.json with strict mode, ESLint flat config with JSDoc enforcement, Prettier configuration, Claude Code plugin manifests (marketplace.json + plugin.json), and the full documentation set (CLAUDE.md, vision, requirements, architecture docs, ADRs 001-009, 11 milestone files, research reports, schema specs, testing strategy, superpower execution plan).
- **ADR-009.** `data/` adopted as the canonical source-data location (deviating from the plan's `source/`); build dynamically discovers versions from `data/{X.Y}/` folders matching `^\d+\.\d+$`; current scope expanded from {3.5, 3.6} to {3.4, 3.5, 3.6}; guides included in v1 wherever the data has them.
- **M1 — Schema mirroring and validation.** Mirrored 19 Zod schemas verbatim from upstream `opensips-docs-collector/src/schemas/` to `scripts/schemas/` with "DO NOT EDIT" headers; deterministic SHA-256 schema-hash check (`npm run schemas:hash`) protects the mirroring contract; dynamic version-discovery stage (`scripts/lib/discover.ts`) pattern-matches `^\d+\.\d+$` and detects optional `guides/` directory per ADR-009; per-file validation stage (`scripts/lib/validate.ts`) maps filenames to Zod schemas and accumulates structured `ValidationIssue`s with parse/schema/io/schema-lookup kinds; orchestrator stub (`scripts/build-references.ts`) wires `npm run validate` end-to-end with the structured exit-code taxonomy from data-pipeline.md §4 (0=success, 2=usage, 3=validation, 5=schema-drift); 51 unit tests across hash/discover/validate.
- **M2 — Core pipeline foundation.** Structured `BuildError` hierarchy with `EXIT_CODES` (`scripts/lib/errors.ts`); filesystem helpers (`atomicWriteFile`, `cleanDirectory`, `ensureDirectory`, `readJsonFile`, `posixPath` in `scripts/lib/fs-helpers.ts`); environment normalization (`normalizeEnvironment` setting `LANG=C LC_ALL=C TZ=UTC` in `scripts/lib/environment.ts`); typed `CliOptions`/`VersionResult`/`BuildSummary` (`scripts/types/cli.ts`); full Commander-based CLI (`scripts/lib/cli-parser.ts`) with all flags from data-pipeline §6.3 (`--only`, `--only-module`, `--dry-run`, `--fail-fast`, `--verbose`, `--quiet`, `--json`, `--source-root`, `--output-root`, `--validate-only`); human + JSON output modes (`scripts/lib/output.ts`); orchestrator (`scripts/build-references.ts`, 165 lines, under the 200-line budget) that delegates per-version processing to `scripts/lib/orchestrator-helpers.ts` (renderers will plug in here in M3-M5 without touching orchestration logic); `npm run build` wired end-to-end with dry-run reporting "would render N modules / N core files / 1 consolidated index" until renderers exist; `npm run clean` script. 92 new tests (36 errors + 19 fs-helpers + 10 environment + 9 cli-parser + 11 output + 7 build-references); 143 total project tests passing.
- **M3 — Per-module rendering.** Foundation libraries: `scripts/lib/markdown-builders.ts` (12 composable helpers including `renderH1-H4`, `renderSection` with empty-omission, `renderTOC`, `toAnchor`); `scripts/lib/frontmatter.ts` (canonical provenance HTML comment per rendering-templates §2.2 with newline/comment-terminator rejection); `scripts/lib/slug.ts` (filename slugifier with collision detection per data-pipeline §2.3); `scripts/lib/validate-markdown.ts` (rendered-Markdown structural validator per rendering-templates §10, fence-aware single-h1 detection, configurable thresholds, length-warn at 1200 / hard-error at 5000 with splitting deferred to a future milestone). Eight per-element renderers under `scripts/render-module/elements/` (`parameter`, `function`, `pseudo-variable`, `mi-command`, `statistic`, `event`, `config-example`, `dependencies`), each with a `headingLevel` parameter prepared for M4 reuse at H2. Module composer (`scripts/render-module/index.ts`) producing complete files in canonical section order (Overview → How It Works → Dependencies → Exported Parameters/Functions/Pseudo-Variables/MI/Statistics/Events → Configuration Examples) with dynamic TOC, alphabetical sub-element ordering, and post-pass collapse of excess blank lines. Orchestrator integration via `scripts/lib/orchestrator-helpers.ts` slug-uniqueness check and per-version atomic writes through `atomicWriteFile`. **194/194 modules render for 3.6, 137/137 for 3.5; build-twice diff is empty (deterministic).** Five validator rules relaxed from error to warning to accommodate legitimate upstream content patterns (raw HTML in descriptions, `#` markers in upstream prose treated as code, skipped heading levels in DocBook-derived content) — full rationale in `scripts/lib/validate-markdown.ts` JSDoc. 283 new tests (35 markdown-builders + 14 frontmatter + 29 slug + 150 element renderers + 17 module composer + 27 markdown validator + 4 module-rendering integration + 7 fix-ups); 426 total project tests passing.

### Known notes for users
- When using `npm run build -- --json`, npm prepends a banner to stdout that breaks JSON consumers. Use `npm run --silent build -- --json` or invoke `npx tsx scripts/build-references.ts --json` directly. Documented because the JSON contract requires clean stdout.

### Notes
- Real-data validation surfaced an upstream JSON-parse defect in `data/3.4/core/variables.json` at byte 80262 (line 1474, column 7 — stray `.0` token mid-object). Per CLAUDE.md Rule 3, the fix belongs upstream in `opensips-docs-collector`, not here. The pipeline correctly detected and reported it; 3.4 builds will continue to fail validation until the extraction is corrected upstream and `data/3.4/` re-mirrored. 3.5 and 3.6 validate clean.
