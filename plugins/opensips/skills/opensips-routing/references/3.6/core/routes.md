## `branch_route`

Request's branch routing block. It contains a set of actions to be taken for each branch of a SIP request.

- **Trigger:** Preparation a new branch (of a request); the branch is well formed, but not yet sent out.
- **Can call routes:** yes

**Syntax:**

```
branch_route[ID]{...}
```

**Example.** Example of usage dropping specific branches..

```opensips_script
route {
        lookup("location");
        t\_on\_branch("1");
        if(!t\_relay()) {
            sl\_send\_reply(500, "Internal Server Error");
        }
    }
    branch\_route\[1\] {
        if($ru=~"10\\.10\\.10\\.10") {
            # discard branches that go to 10.10.10.10
            drop();
        }
    }
```

## `error_route`

The error route is executed automatically when a parsing error occurs during SIP request processing, or when a script assert fails.

- **Trigger:** Parsing error in "route".
- **Can call routes:** yes

**Available variables:** `$(err.class)`, `$(err.level)`, `$(err.info)`, `$(err.rcode)`, `$(err.rreason)`

**Syntax:**

```
error_route{...}
```

**Example.** Example of usage logging error details..

```opensips_script
error\_route {
     xlog("--- error route class=$(err.class) level=$(err.level)
            info=$(err.info) rcode=$(err.rcode) rreason=$(err.rreason) ---\\n");
     xlog("--- error from \[$si:$sp\]\\n+++++\\n$mb\\n++++\\n");
     sl\_send\_reply("$err.rcode", "$err.rreason");
     exit;
  }
```

## `event_route`

The event_route is used by the OpenSIPS Event Interface to execute script code when an event is triggered.

- **Trigger:** The event_route module when an event raised by the OpenSIPS Event Interface.
- **Can call routes:** no

**Syntax:**

```
event_route[E_EVENT_NAME]{...}
```

**Example.** Example of usage handling an event..

```opensips_script
event\_route\[E\_PIKE\_BLOCKED\] {
    xlog("The E\_PIKE\_BLOCKED event was raised\\n");
  }
```

## `failure_route`

Failed transaction routing block. It contains a set of actions to be taken each transaction that received only negative replies (>=300) for all branches.

- **Trigger:** Receiving or generation(internal) of a negative reply that completes the transaction (all branches are terminated with negative replies).
- **Can call routes:** yes

**Syntax:**

```
failure_route[ID]{...}
```

**Example.** Example of usage relaying failed INVITEs to voicemail..

```opensips_script
route {
        lookup("location");
        t\_on\_failure("1");
        if(!t\_relay()) {
            sl\_send\_reply(500, "Internal Server Error");
        }
    }
    failure\_route\[1\] {
        if(is\_method("INVITE")) {
             # call failed - relay to voice mail
             t\_relay("udp:voicemail.server.com:5060");
        }
    }
```

## `local_route`

The local route is executed automatically when a new SIP request is generated by TM, internally (no UAC side). This is a route intended to be used for message inspection, accounting and for applying last changes on the message headers.

- **Trigger:** TM generating a brand new request.
- **Can call routes:** no

**Syntax:**

```
local_route{...}
```

**Example.** Example of usage appending headers and accounting..

```opensips_script
local\_route {
     if (is\_method("INVITE") && $ru=~"@foreign.com") {
        append\_hf("P-hint: foreign request\\r\\n");
        exit;
     }
     if (is\_method("BYE") ) {
        acc\_log\_request("internally generated BYE");
     }
  }
```

## `onreply_route`

Reply routing block. It contains a set of actions to be taken for SIP replies.

- **Trigger:** Receiving of a reply from the network.
- **Can call routes:** yes

**Syntax:**

```
onreply_route {...} or onreply_route[0]{...} or onreply_route[ID]{...}
```

**Example.** Example of usage showing global, per transaction, and per branch reply handling..

```opensips_script
route {
        seturi("sip:bob@opensips.org");  # first branch
        append\_branch("sip:alice@opensips.org"); # second branch

        t\_on\_reply("global"); # the "global" reply route
                              # is set the whole transaction
        t\_on\_branch("1");

        t\_relay();
}

branch\_route\[1\] {
        if ($rU=="alice")
                t\_on\_reply("alice"); # the "alice" reply route
                                      # is set only for second branch
}

onreply\_route {
        xlog("OpenSIPS received a reply from $si\\n");
}

onreply\_route\[alice\] {
        xlog("received reply on the branch from alice\\n");
}

onreply\_route\[global\] {
        if (t\_check\_status("1\[0-9\]\[0-9\]")) {
                setflag(1);
                log("provisional reply received\\n");
                if (t\_check\_status("183"))
                        drop;
        }
}
```

## `route`

Request routing block. It contains a set of actions to be taken for SIP requests.

- **Trigger:** Receiving an external request from the network.
- **Can call routes:** yes

**Syntax:**

```
route{...} or route[0]{...} or route[ID]{...}
```

**Example.** Example of usage handling OPTIONS and forwarding..

```opensips_script
route {
         if(is\_method("OPTIONS")) {
            # send reply for each options request
            sl\_send\_reply(200, "OK");
            exit();
         }
         route(1);
    }
    route\[1\] {
         # forward according to uri
         forward();
    }
```

**Example.** Example of passing values using the return variable..

```opensips_script
route {
         route(query);
         xlog("Query returned id $return(0) with $return(1) values\\n");
    }
    route\[query\] {
         # perform a query for information and store the information in $var(id) and $var(values)
         return(1, $var(id), $var(values));
    }
```

## `startup_route`

The startup_route is executed only once when OpenSIPS is started and before the processing of SIP messages begins.

- **Trigger:** At startup, before the listener processes are started.
- **Can call routes:** no

**Syntax:**

```
startup_route{...}
```

**Example.** Example of usage loading data into cache..

```opensips_script
startup\_route {
    avp\_db\_query("select gwlist where ruleid==1",$avp(i:100));
    cache\_store("local", "rule1", "$avp(i:100)");
  }
```

## `timer_route`

The timer_route is a route executed periodically at a configured interval of time specified next to the name (in seconds).

- **Trigger:** The timer worker process.
- **Can call routes:** no

**Syntax:**

```
timer_route[name, interval]{...}
```

**Example.** Example of usage updating gateway list periodically..

```opensips_script
timer\_route\[gw\_update, 300\] {
    avp\_db\_query("select gwlist where ruleid==1",$avp(i:100));
    $shv(i:100) =$avp(i:100);
  }
```
