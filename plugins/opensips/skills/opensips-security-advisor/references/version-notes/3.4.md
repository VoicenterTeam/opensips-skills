# OpenSIPS 3.4 — Version Notes

This document captures the version-specific deltas, known CVEs, module-set context, and migration concerns relevant to advisor rules that target the OpenSIPS 3.4 release line.

OpenSIPS 3.4 is the **previous LTS line** at the time of this skill's authoring. It remains in active deployment in many production environments and is supported with security patches through its declared EOL.

---

## Release line

- **First release.** OpenSIPS 3.4.0 (2022-11).
- **Latest patchlevel.** Consult upstream — patchlevels are released as security and stability fixes accumulate.
- **EOL status.** LTS line; consult the OpenSIPS release calendar for current EOL date.

---

## Known CVEs in this release line

The following CVE entries are derived from `../knowledge/vulnerability-reference.md` § 12 and verified against NVD, VulnCheck, AISLE Research, and Enable Security's 2022 OpenSIPS audit report as of April 2026.

### CVE-2026-25554 — auth_jwt SQL injection

- **Affected on 3.4 line.** All 3.4.x patchlevels prior to the backport patchlevel.
- **Fixed in.** OpenSIPS 3.6.4 on the 3.6 line; corresponding backport on 3.4.x. Verify against the OpenSIPS release notes for the exact patched 3.4.x.
- **CVSS 4.0.** `CVSS:4.0/AV:N/AC:L/AT:P/PR:N/UI:N/VC:H/VI:L/VA:N/SC:N/SI:N/SA:N` — score 8.3.
- **CWE.** CWE-89 (SQL Injection).
- **Summary.** See `3.6.md` § "CVE-2026-25554" for full details.
- **Cited by rules.** `OSIPS-SEC-AUTH-004` (projected).

### Enable Security 2022 audit cluster (CVE-2023-27597 through 28099)

The 2022 audit by Sandro Gauci and Alfred Farrugia of Enable Security disclosed a cluster of parser-crash and DoS vulnerabilities, all fixed in 3.1.x and 3.2.x patchlevels. Some are relevant to operators upgrading from earlier versions to 3.4 — a 3.4 deployment using a recent patchlevel inherits the fixes, but version-gated rules detecting the underlying patterns (e.g., calls to `ds_is_in_list()` without `$si` as first arg) may still be useful for hardening.

| CVE | Title | CVSS | Fixed in |
|---|---|---|---|
| CVE-2023-27597 | parse_uri() crash | 7.5 | 3.1.7 / 3.2.4 |
| CVE-2023-27598 | parse_via() crash | 7.5 | 3.1.7 / 3.2.4 |
| CVE-2023-27599 | parse_to_param() crash | 7.5 | 3.1.7 / 3.2.4 |
| CVE-2023-27600 | codec_delete_XX() crash | 7.5 | 3.1.7 / 3.2.4 |
| CVE-2023-27601 | codec_delete_XX() crash (variant 2) | 7.5 | 3.1.7 / 3.2.4 |
| CVE-2023-28095 | local negative reply construction crash | 7.5 | 3.1.7 / 3.2.4 |
| CVE-2023-28097 | Content-Length parser crash | 7.5 | 3.1.9 / 3.2.6 |
| CVE-2023-28098 | Digest Authentication parser crash | 5.9 | 3.1.7 / 3.2.4 |
| CVE-2023-28099 | ds_is_in_list() crash on invalid input | 5.9 | 3.1.9 / 3.2.6 |

Per Enable Security's analysis, all of these result in DoS rather than RCE. Full audit report: `https://opensips.org/pub/audit-2022/opensips-audit-technical-report-full.pdf`.

- **Cited by rules.** Future: version-gated rules in `dos_defense` and `config_hygiene` families targeting cfgs running pre-patch 3.1.x or 3.2.x.

## Module set notes

The following modules are notable for security analysis on the 3.4 line. This is not an exhaustive module list — it focuses on modules whose presence or absence affects rule applicability.

- `mi_http`, `mi_fifo`, `mi_datagram` — management-interface modules.
- `tls_mgm` — TLS configuration manager (per-domain TLS profile management). Module exists in 3.4 with the post-3.0 listener-scoped parameter syntax.
- `auth`, `auth_db`, `auth_jwt`, `auth_radius` — authentication backends.
- `pike`, `ratelimit` — DoS-defense modules.
- `permissions` — IP-based and URI-based authorization.
- `signaling`, `sl`, `tm`, `rr`, `maxfwd`, `sipmsgops`, `textops` — core signaling and message-handling modules.

Modules **not present** in 3.4 that exist in later versions:
- `tls_wolfssl` — introduced in 3.6 (alternative TLS backend). Rules referencing this module must gate on `applies_if_opensips_version: ">=3.6"`.
