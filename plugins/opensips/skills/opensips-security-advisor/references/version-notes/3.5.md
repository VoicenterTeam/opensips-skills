# OpenSIPS 3.5 — Version Notes

This document captures the version-specific deltas, known CVEs, module-set context, and migration concerns relevant to advisor rules that target the OpenSIPS 3.5 release line.

OpenSIPS 3.5 is an **active LTS line** at the time of this skill's authoring, widely deployed in production. The reference fixtures `clean-l1-enterprise-pbx.cfg` and `custom-sanitizer.cfg` declare 3.5.4 as their target version.

---

## Release line

- **First release.** OpenSIPS 3.5.0 (2023-11).
- **Latest patchlevel.** Consult upstream — patchlevels are released as security and stability fixes accumulate. The reference fixtures pin 3.5.4 as the assumed-current patchlevel at fixture authoring time.
- **EOL status.** Active LTS; consult the OpenSIPS release calendar.

---

## Known CVEs in this release line

The following CVE entries are derived from `../knowledge/vulnerability-reference.md` § 12 and verified against NVD, VulnCheck, and AISLE Research as of April 2026.

### CVE-2026-25554 — auth_jwt SQL injection

- **Affected versions on 3.5 line.** All 3.5.x patchlevels prior to the backport patchlevel (verify against OpenSIPS release notes for exact 3.5.x patched version).
- **Fixed in.** OpenSIPS 3.6.4 on the 3.6 line; corresponding backport on 3.5.x. The reference fixture pins 3.5.4 as the fixture's target and treats it as **unpatched on the 3.5 line** for fixture purposes — this is conservative and may need confirming against the actual backport patchlevel.
- **CVSS 4.0.** `CVSS:4.0/AV:N/AC:L/AT:P/PR:N/UI:N/VC:H/VI:L/VA:N/SC:N/SI:N/SA:N` — score 8.3.
- **CWE.** CWE-89 (SQL Injection).
- **Summary.** See `3.6.md` § "CVE-2026-25554" for full details. Same vulnerability, same root cause, same fix mechanism.
- **Cited by rules.** `OSIPS-SEC-AUTH-004` (projected).

## Module set notes

The 3.5 module set is broadly compatible with 3.4. Notable items:

- All 3.4 modules continue to exist on 3.5.
- `auth_jwt` — present in 3.5. Note: 3.5 patchlevels prior to 3.5.4 are within the CVE-2026-25554 vulnerable range when `db_mode=1`. Rules detecting this CVE should fire on 3.5.0 through 3.5.3 inclusive. Verify exact patched version against the CVE record in `../knowledge/vulnerability-reference.md`.
- `tls_mgm` — listener-scoped parameter syntax stabilized in this line. The `[default]`, `[domain_name]`, and per-listener `[ip:port]` profile selectors all behave consistently across 3.5 patchlevels.

---

## Migration concerns from 3.4

The following deltas matter for security-advisor purposes when an operator upgrades a 3.4 cfg to 3.5:

- **Pseudovariable behavior.** No breaking pseudovariable changes between 3.4 and 3.5. Cfgs that worked under 3.4 generally work under 3.5 unmodified.
- **Module API.** `auth_jwt` API extended in 3.5 to support additional JWT validation modes; existing 3.4 cfgs continue to work without modification.
- **Default values.** No changes to advisor-relevant module default values that would silently flip a cfg from clean to vulnerable.
- **Removed modules.** None material to current rule set.

Operators upgrading from 3.4 to 3.5 should:
1. Confirm `auth_jwt` modparams remain meaningful (parameter names unchanged, value ranges unchanged).
2. Re-run the advisor against the upgraded cfg with the 3.5 version notes applied — version-gated CVE rules may newly apply.
