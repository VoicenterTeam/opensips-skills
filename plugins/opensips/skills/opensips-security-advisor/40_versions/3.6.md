# OpenSIPS 3.6 — Version Overlay

This document captures the version-specific deltas, known CVEs, module-set context, and migration concerns relevant to advisor rules that target the OpenSIPS 3.6 release line.

OpenSIPS 3.6 is the **current LTS line** at the time of this skill's authoring. The reference fixture `vulnerable-mixed.cfg` declares 3.6.2 as its target version (deliberately within the CVE-2026-25554 vulnerable range).

## Known CVEs in this release line

The following CVE entries are derived from `90_reference/01_master_vulnerability_reference.md` § 12 (CVE Inventory) and verified against NVD, VulnCheck, and AISLE Research as of April 2026.

### CVE-2026-25554 — auth_jwt SQL injection (JWT authentication bypass)

- **Affected versions.** OpenSIPS 3.1 through 3.6.4 (prior to commit `3822d33`), with `auth_jwt` module loaded and `db_mode` enabled (DB-backed JWT key lookup). Deployments using only `jwt_script_authorize()` with script-provided keys are unaffected.
- **Fixed in.** OpenSIPS 3.6.4. Backports to 3.5.x and 3.4.x exist; verify against the OpenSIPS release notes for the exact patched patchlevel on each line.
- **CVSS 4.0.** `CVSS:4.0/AV:N/AC:L/AT:P/PR:N/UI:N/VC:H/VI:L/VA:N/SC:N/SI:N/SA:N` — score **8.3**.
- **CWE.** CWE-89 (SQL Injection).
- **Summary.** The function `jwt_db_authorize()` in `modules/auth_jwt/authorize.c` extracts the `tag` claim from a JWT *before* signature verification and incorporates the unescaped value directly into a SQL query. An attacker supplies a crafted JWT with a malicious `tag` claim to manipulate the query result and bypass JWT authentication, allowing impersonation of arbitrary identities listed in the JWT profiles table.
- **Discovered by.** Pavel Kohout, AISLE Research. Disclosed January 2026; fixed February 2, 2026.
- **Fix.** Upgrade to 3.6.4+ (or backport-patched versions on 3.4.x / 3.5.x), or set `db_mode=0` (file-loaded JWT keys via `jwt_script_authorize()`) as interim mitigation.
- **Cited by rules.** `OSIPS-SEC-AUTH-004` (jwt-db-mode-cve, projected — not yet authored).
- **Note.** Fixtures and rule frontmatter authored in earlier sessions used `VC:H/VI:H/VA:H` (9.3) and CWE-287 — these are wrong and have been corrected during the consolidation pass dated 2026-04-29 to match the published values above.

## Module set notes

The 3.6 module set adds a notable new module:

- **`tls_wolfssl`** — alternative TLS backend using the WolfSSL library. Introduced in 3.6 as a build-time alternative to OpenSSL. Rules referencing this module must declare `applies_if_opensips_version: ">=3.6"` to avoid skipped-rule diagnostics on earlier versions.

  Security implications:
  - WolfSSL has a different cipher-suite vocabulary than OpenSSL. Rules targeting cipher-list values (e.g., `OSIPS-SEC-TLS-004` weak-ciphers checks, projected) will need version-gated value patterns: one for `tls_mgm`+OpenSSL syntax, one for `tls_wolfssl` syntax.
  - `tls_wolfssl` and `tls_mgm` are mutually exclusive at runtime — a cfg may load one but not both. Rules detecting "no TLS configured" must check for both.

- All 3.5 modules continue to exist on 3.6 with API compatibility maintained.

- `auth_jwt` — present in 3.6 with the CVE-2026-25554 fix landed at 3.6.4 (per fixture and rule assumptions; confirm against Phase 2 reference). 3.6.0 through 3.6.3 are vulnerable.

## Migration concerns from 3.5

- **Pseudovariable behavior.** No breaking pseudovariable changes between 3.5 and 3.6.
- **Module API.** `tls_wolfssl` is opt-in; existing 3.5 cfgs using `tls_mgm` continue to work unmodified on 3.6.
- **Default values.** No changes to advisor-relevant module default values.
- **Behavioral changes.** `event_route[E_DLG_STATE_CHANGED]` and other dialog-event routes had minor signature adjustments in 3.6. Cfgs using these should be reviewed against the upstream changelog.

Operators upgrading from 3.5 to 3.6:
1. Decide whether to migrate from OpenSSL (`tls_mgm`) to WolfSSL (`tls_wolfssl`). Either is supported.
2. Re-run the advisor with the 3.6 overlay — CVE-2026-25554 detection becomes critically relevant for cfgs on 3.6.0 through 3.6.3.
